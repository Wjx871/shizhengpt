# 图像、文本及联合问诊：幻觉约束试验

2026-10-08。本次针对原来的面部图像和文字问诊流程，不涉及 TongueDx2 舌诊标签测试。

已经实现并在服务器运行了一版外围优化。它改善了原始症状保留、图片不可用时的处理和部分已知错误的拦截；仍存在可疑视觉描述，不能认定幻觉已消除，也没有验证临床诊断准确率。

## 改动

- 症状原文由程序保存在 `user_symptoms` 和 `source_symptoms`，解释通过 S 编号引用依据，不再让模型负责重写用户自述。
- 先进行面部质控。没有图片或图片被拒绝时跳过视觉推理，有文字症状仍可继续追问。
- 视觉观察和问诊分开生成。第一步只要求照片技术描述；第二步使用症状原文、视觉状态及未核验的描述，不再次输入图片，也不允许根据照片颜色做中医辨证。
- 检查格式、症状编号、部分程度/频率/否定改写、人口学猜测、不可见身体信息及确定性断言。最多重试一次，失败内容不作为有效分析展示。
- 区分询问未知症状与预设症状存在。例如允许“是否存在失眠或多梦？”，拒绝将“睡眠质量一般”预设为“睡眠质量差”的追问。

入口：[guarded_consultation.py](../scripts/guarded_consultation.py)，操作说明：[guarded_consultation_usage.md](guarded_consultation_usage.md)。没有训练、修改模型权重或更改服务器 BF16 配置。

## 实验与可核查结果

12 个输入条件：原始/变暗/偏蓝/过亮面图、局部脸图、非人脸图；两组文字；原图联合、局部图联合、无图联合、完整公开照片与新文字组合。图片以同一公开人物为主，症状均为合成输入。这是开发回归实验，不是独立患者验证集。

整个优化过程实际调用模型 **52 次**：首次基线和保护流程 28 次、修改后的保护流程 14 次、六个文字/联合条件再次生成 10 次。最终报告复用了第二轮视觉记录；规则复核没有新增生成，不能把复用记录重复计入推理次数。

| 核对项 | 最终结果 | 解释 |
|---|---:|---|
| 有症状的条件保留原文 | 6/6 | 程序字段逐项一致；这是程序保证 |
| 有症状的条件保留非空解释和追问 | 6/6 | 通过当前有限规则，仍需人工复核 |
| 保留技术描述的图像条件 | 5 | 原始、变暗、偏蓝、原图联合、完整照片联合；不是五位患者 |
| 图片被质控拒绝 | 4 | 过亮、局部脸、非人脸、局部脸联合；均零视觉调用、零视觉事实 |
| 无图条件 | 3 | 两个文字条件和无图联合；均零视觉调用、零视觉事实 |
| 最终保留记录中的候选回答 | 17 | 含复用视觉候选及再次生成的文字候选 |
| 当前规则仍拒绝的候选 | 2 | 均为视觉 JSON 格式失败，随后重试通过 |
| 实际发生重试的条件 | 6 | 两个视觉格式重试、四个文字规则重试 |
| 旧基线截断 | 5/12 | 五个面图回答达到 512 token 上限 |
| 最终候选截断 | 0/17 | 不代表内容医学正确 |

四个文字重试由当时过严的追问规则触发：它把询问“多梦”等未知症状误判为编造。修正规则后，原有候选均重新检查，原始文本没有被改写，旧检查原因和复核前文件均保留。最终选择每个条件最后一个通过的候选；不能将这些误拦截计为成功发现四次幻觉。

基线与最终条件清单和图像哈希一致，模型配置一致：ShizhenGPT-7B-VL、BF16、eager attention、`do_sample=false`、seed 42、像素范围 3136–1003520。实际基线与问诊生成上限为 512 tokens，技术视觉生成上限为 256 tokens；配置文件中的默认上限 768 不等于实际调用上限。各流程的提示、输出范围、长度上限、分步和重试机制不同，属于组合干预，不能归因于某一个模块。基线截断也使全文幻觉率比较不成立。

## 具体前后对照

| 输入或错误 | 旧输出 | 优化后的处理 |
|---|---|---|
| 用户“睡眠质量一般” | 自述改成“睡眠质量差”，解释添加“睡眠浅” | 原文原样保存，追问“睡眠质量一般具体表现为入睡困难/易醒还是多梦？”；仍可进一步改成更开放的“具体指什么” |
| 局部脸照片 | 无依据断言“11岁女性”，还描述对侧脸颊等信息 | 质控拒绝，跳过视觉生成，不输出这些描述 |
| 局部图与症状联合 | 实际传入图片，却声称“未提供图片”；解释改写睡眠程度 | 程序记录 `image_present=true` 与质控拒绝状态；继续基于文字症状追问 |
| 偏蓝照片 | 根据颜色推断脾胃、肝、肺、肾等解释 | 仅保留面部轮廓/头发等技术描述；停止该照片颜色的辨证输出 |

这些改善中，症状存储和路由是可验证的软件行为，视觉诊断输出减少则来自范围收缩。不能据此声称模型本身视觉理解能力提高。

## 仍存在的问题

完整公开照片的视觉描述仍出现“佩戴橙色宇航服头盔，头盔内衬黑色材质”这一可疑断言，需要逐图核验；还保留“无明显可见皮疹或异常色泽变化”，原图也有“无明显肿胀或畸形”这类负面判断。它们通过了关键词规则，但通过检查不能证明照片事实正确或足以排除异常。

变暗和偏蓝图本次都通过了基础技术质控。质控主要检查人脸/眼部检测、清晰度和像素裁切比例，并没有证明光照和颜色适合医学判断。眼部检测也不能保证每个面部区域可见，规则无法覆盖全部近义词、错误前提及证候推理。

原始模型回答仍保存在研究记录中，不能直接作为患者端有效结论展示。原来较详细的辨证内容被压缩为有限技术描述和谨慎追问，存在信息损失；不能把输出变少等同于准确率提高。

## 下一步优先级

1. 建立独立、人工标注的失败样本集。分别标注症状事实、否定/程度/时间、图片逐区域可见性与具体断言；报告错误率、回答覆盖率、误拒率和延迟。按患者划分开发集与测试集，冻结规则后再评估。
2. 优先完善输入事实和追问核验：用结构化症状槽位与原文证据跨度，比对否定、程度、频率和持续时间；检测问句中的错误前提。每个可能解释仍要引用原始依据，编号有效不等于推理成立。
3. 加强逐区域遮挡和光照质控，补充真实低照度、强偏色和遮挡样本。对不能确认的细微异常使用“无法判断”，避免“未见异常”被误解为排除疾病。
4. 对保留的视觉断言引入人工复核或独立视觉核验，并验证核验器自身的错误率。仅再问同一模型“有没有幻觉”不能作为正确性证据。
5. 有足够专家审核案例后，再做针对性微调或偏好训练。检索可为医学解释提供来源，但不能修复照片看错或用户症状改写。

可以向师兄汇报：**已做一版流程层面的幻觉约束并完成服务器回归测试，重点改善症状原文保留、图片质控、分步生成和输出核验；视觉描述仍有可疑内容，后续需要独立标注集和更细的事实核验，尚未验证临床可靠性。**
