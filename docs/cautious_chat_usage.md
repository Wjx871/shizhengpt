# 谨慎回答：信息不足时弃答

2026-10-13。网页默认模式现为“谨慎回答”；“原始模型（未核对）”用于对照。切换模式会新建对话。底座仍是原始 ShizhenGPT-7B-VL，没有继续微调。

2026-10-15 更新：默认谨慎流程为 v2。它保留程序可测的图片分辨率、彩色像素及质控信息，仍弃答未核验的医学细节；改进礼貌前缀、假设语句和用药话题的处理。参见 [v2 对照报告](cautious_chat_v2_report_20261015.md)。旧版 API 可显式传 `mode: "guarded_v1"` 做对照，新默认仍传 `mode: "guarded"`。

## 这版做什么

- 图片先做曝光、分辨率和既有面部质控。不合格时提示无法可靠判断和重新拍摄。
- 即使清晰图片通过质控，也不展示未经独立核验的自由视觉描述、肤色或病变判断。此时明确提示“图片信息尚不能确认”。这是输出能力的收窄，不是提高视觉识别准确率。舌头和其他部位不适用当前面部流程。
- 文本症状按用户原字串保留，引用必须对应来源。冲突信息先追问；明确“更正”后使用更正后的症状，旧条目仍在会话历史中。
- 基于 v4.1 的模型解释需再次通过不确定性表达、证据和部分新增症状检查。未通过的解释不展示，改为无法确定病因或证候，保留经过有限检查的追问。
- 无法识别的症状、没有可核查资料的知识问题，会说明当前不能可靠回答。已有少量固定帮助内容（如问诊需要提供哪些信息）仍可正常回答。

## 能力边界

有限词表、引用检查和不确定性措辞不能证明医学解释成立，也无法涵盖所有幻觉。模型可能以“可能”开头却仍提出缺乏医学依据的方向；当前没有医生审核病例和可信医学检索库。不能保证零幻觉，不能把“有限核对”当作诊断正确。

当前模式会放弃全部自由视觉细节，包括清晰照片的细节描述。陌生症状或一般知识问题也可能被保守拒绝，需要继续记录误拒和可用性损失。原始模式仍可能编造，页面会明确标为未核对。

## 服务与接口

沿用 [网页启动方式](chat_web.md)。服务器执行 `scripts/chat_server.py`，默认接口模式为 `guarded`；要请求原始模型，必须显式传 `mode: "raw"`。旧评测脚本若使用聊天 API，需要显式指定原始模式，不能把谨慎流程输出当作原模型结果。历史冻结的评测文件没有修改。

每个会话保存用户原文与最近一张图片；后续追问可使用前文。候选解释、拒绝原因和图片质控记录只保存在服务器会话内存的 `last_guard_trace` 中，不把被拒绝的内容返回网页。新对话和过期清理同时清理会话与临时图片。服务重启不会恢复旧对话。
