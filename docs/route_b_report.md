# Route B：面部质控、照片像素测量与 ShizhenGPT 对照实验

这是原部署与 117 次评测后的追加实验。模型继续使用官方原始 BF16 权重、K100_AI 和 eager attention，未训练或量化。本文统计来自服务器实际输出，属于工程验证，未经临床验证。

## 结果与建议

**已实现 CPU 面部质控和像素测量原型，并完成 78 次受控推理。质控适合在程序层拦截不合格输入；把 CV 信息传给模型尚未证明能提升事实忠实度。** 模型会复述限制，也会改变字段类型、改写数值，甚至在质控拒绝后继续描述皮肤。

保留程序测量和原始症状作为独立数据，模型描述始终标记为未经核验。下一步应先收集有授权、标准采集条件和专家标注的临床样本，再验证检测、质控阈值和模型效果。现有证据不支持直接进行面色辨证或疾病分类。

## 比较方法

两组使用相同提示要求、实际图片、图片是否存在的显式状态及症状列表。唯一干预是 `cv_measurements`：A 组为 null，B 组提供 CV 事实。两组均要求不猜测年龄、性别、疾病或证候；输出五字段 JSON；保留症状原字串；无图时不生成视觉事实。

13 个条件：同一 NASA 正脸照片的原图、调亮、调暗、偏黄、偏蓝、模糊、JPEG 七种版本；局部脸图、理论面部示意图、无关几何图形；正脸+症状、局部脸+症状、无图+症状。每组每条件重复 3 次，共 78 次，`do_sample=False`，输出上限 512 tokens。图像变体使用固定原图采样位置，避免定位漂移影响颜色比较；模型收到原始未标注图片。

症状是构造的实验输入：`最近容易疲劳`、`手脚较凉`、`睡眠质量一般`、`偶尔食欲不佳`，不是照片人物的真实自述。NASA 七种版本属于同一个人，同一条件的三次重复不是独立病例。本轮 A 组与早期原始评测提示不同，因此不能把前后结果差异归因于 CV。

在 B 组比较实验中，质控拒绝的条件仍生成答案，用于观察模型是否遵守拒绝信息，记录 `ablation_bypassed_gate=true`。程序给出的 `gated_pipeline_result` 是门控行为的记录，不是另一次独立推理；实际入口 `infer_face_qc.py` 会在质控失败时停止，不加载模型。预运行和模板调试输出另存，未计入正式 78 次。

| 指标 | A：相同提示，无 CV 信息 | B：相同提示，带 CV 信息 |

| 推理成功 | 39/39 | 39/39 |
| 输出达到 token 上限 | 0/39 | 0/39 |
| 严格五字段及字段类型合规 | 3/39 | 6/39 |
| 三个融合条件中症状逐字一致 | 9/9 | 9/9 |
| 无图条件 visual_facts 为空 | 3/3 | 3/3 |
| 条件内三次原始输出完全相同 | 13/13 条件 | 13/13 条件 |
| 单次推理中位耗时，含预处理、不含模型加载 | 3.34 秒 | 8.76 秒 |

正式模型加载约 55.13 秒；78 次推理循环约 542.49 秒。最大 PyTorch allocated 显存约 16.04 GiB，最大 reserved 16.30 GiB。12 个带图条件的 CPU 质控中位耗时约 0.063 秒，不含大模型处理。B 组生成内容通常更长，耗时差异包含更长输入和输出，不能解释为 CV 算法的耗时。

严格合规检查要求四个列表均为字符串列表，`medical_status` 必须为 `unknown`。Markdown JSON 代码围栏允许剥除。缺字段、中文标点导致 JSON 无法解析、列表变字符串或对象列表均判失败。症状保真与无图空视觉单独检查，不要求其它字段同时合规。指标不评估临床正确性，合规也不代表事实正确。

B 组通过格式检查的是局部脸图和无图条件；局部脸图仍违反质控要求，且 `measurement_facts` 写的是限制而非测量数值。因此 6/39 不能视为可靠答案率。原图、调暗、偏黄、模糊、JPEG 的 A 组复用了相同的“清晰度良好，肤色均匀，无明显光影干扰”描述，未充分反映输入变化。

## 质控与测量实现

使用服务器已有 OpenCV 4.12.0 的 Haar 正脸定位，再验证两眼相对位置。原始候选框、验证结果与检测器文件哈希均保存。完整 NASA 照片有两个原始候选，其中背景误检没有通过眼部验证；理论示意图上的候选同样未通过。这里只验证了这些固定样本，不能据此给检测器准确率。

定位后用两个几何采样框记录 RGB 中位数、OpenCV 浮点 Lab 中位数、灰度均值和像素通道饱和比例。它们不是皮肤分割区域；坐标表示图像左/右，不能替代人体解剖左右。标注图已人工查看用于工程位置核查，不属于医学评分。

质控阈值是工程启发式参数：正脸短边至少 80 px；不足 200 px 提醒细节不足；Laplacian 方差小于 50 拒绝、小于 170 提醒；曝光或采样区高通道饱和比例大于 0.30 拒绝；近单色比例至少 0.98 拒绝颜色分析；正脸眼部验证必须恰好一个；非默认 EXIF 方向要求先统一预处理。阈值尚未做敏感度、特异度或不同肤色人群验证。

13 条件中 6 条通过、7 条拒绝。拒绝条件为调亮、偏黄、局部脸图、示意图、几何图形、局部脸+症状、无图+症状。模糊版只产生低清晰度提醒，未被拒绝。所有 NASA 裁剪版的脸宽约 97 px，均有细节分辨率提醒。无图拒绝表示不能进行面部分析；一般文本问诊仍可用原始文本推理入口。

## 可运行入口与验证

服务器项目目录：`/root/private_data/shizhengpt-evaluation`。

```bash
# 仅 CPU 质控与像素统计
.venv/bin/python scripts/face_quality.py --image evaluation/images/face/astronaut_original.png --output evaluation/route_b/qc.json

# 质控通过后才加载模型；模型内容始终需要核查
.venv/bin/python scripts/infer_face_qc.py --image evaluation/images/face/astronaut_original.png --output evaluation/route_b/face_result.json

# 可选症状：UTF-8 JSON 文件，内容是字符串列表
# 上述命令加 --symptoms-json /path/to/symptoms.json

# 文本问诊仍走已有入口
.venv/bin/python scripts/infer_image.py --prompt '我最近容易疲劳，请给出需要追问的问题。'
```

`infer_face_qc.py` 保留顶层 `cv_facts`、原始 `user_symptoms` 和 `medical_status=unknown`；不把模型复述作为程序测量。拒绝时 `model_invoked=false` 且 action 为 `reject_before_model_load`。通过时 action 为 `generated_unverified_description`，`model_description_verified=false`，`requires_review=true`；另外记录 JSON 合规和症状保真。

已分别验证局部脸的拒绝路径和正脸的通过路径，证据是 `wrapper_reject_test.json`、`wrapper_pass_test.json`。通过质控不是健康判断，也不说明模型答案通过了事实核验。比较实验的所有正式原始输出、CSV、测量和汇总均已保留；原 117 次评测不改写。

## 后续研究边界

目前只是小规模原型，没有皮肤分割、姿态/遮挡完整验证、肤色校准、多相机或多人泛化验证，没有临床真值。未实现 Tongue CV、疾病分类、RAG 或 Agent。

建议先将质控提示、数值和原始症状通过程序直接展示，暂不依赖模型转换这些字段。临床评测需要有授权的真实照片、标准拍摄、专家标注和独立测试集；之后分别评价质控误拒绝、视觉描述、症状追问及辨证，不把同一人的处理变体当作独立病例。
