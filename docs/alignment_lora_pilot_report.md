# 视觉事实、症状程度与证据引用：首轮 LoRA 试验

2026-10-09。实际进行了参数训练，区别于前两轮外围规则优化。

**专门的事实任务有改善，完整问诊出现明显输出收缩。适配器保留为事实核验研究候选，原始问诊入口继续使用原模型；本轮没有替换默认模型。**

## 数据与训练

- 64 条训练记录：16 条图片可见性/图像类型、24 条症状原文及状态/程度/频率/时间提取、24 条陈述纠正和证据编号对应。
- 视觉训练只有 5 个图片文件，16 条记录包含重复；公开人物完整图和裁剪图是同一个人。描述与可见性由助手核对，不是医生标注；没有使用疾病、证候或治疗标签。
- 测试在训练前冻结：16 条输入，分为 4 条视觉、6 条症状、6 条引用。视觉测试实际只有新取出的眼部照片 `6986.jpg` 和示意图 `5209.jpg` 两个文件，每张使用两种提示。
- 训练/测试图片 SHA256 无重合，完整的图像＋提示或文本提示没有进入另一集合。没有患者 ID，无法确认训练/测试患者不同，也不能判断原始预训练是否见过这些图片。[协议措辞复核](../evaluation/alignment_lora_pilot_20261009/protocol_review.json)记录了这一限制，冻结协议未被修改。
- 另有 4 条此前的图文/描述问诊提示检查迁移与退化。它们用于开发，图片/症状类型可能与训练重合，不是独立测试。

模型仍是 ShizhenGPT-7B-VL、原始 BF16、eager attention，沿用服务器原 PyTorch 2.5.1 和现有 PEFT 0.17.1，未升级环境。LoRA 仅加到语言侧 attention 的 q/v 投影，r=8、alpha=16、dropout=0；**视觉编码器冻结**。可训练参数 2,523,136，LoRA 参数为 FP32，基础权重保持 BF16。

训练固定一轮、64 个优化步、batch=1、学习率 0.0002。监督只作用于 assistant 回答，提示与图片 token 的标签设为 -100；没有截断训练输入，完成前缀 token 边界一致性检查。训练约 32.96 秒，峰值 allocated 约 16.92 GiB。所有基础参数无梯度，嵌入及输出权重抽样值未变，优化器仅包含 LoRA 参数；原始权重文件不是保存目标。

只保存并评估了固定的最终 checkpoint，没有根据测试挑选或重训。训练损失下降表示拟合这批小样本，不是临床准确率。

## 40 次实际评测

原模型与适配器各运行 20 条输入，共 **40 次真实生成**，没有拦截、规则修复或重试。16 条事实任务上限 512 tokens，4 条迁移问诊上限 768 tokens，均关闭采样；两组 JSON 均能解析，0 次截断。

| 专门任务 | 原模型 | LoRA | 能说明什么 |
|---|---:|---:|---|
| 视觉目标完整一致 | 0/4 | 3/4 | 输出格式及可见性/保守状态更符合本任务要求 |
| 视觉字段一致 | 16/24 | 22/24 | 每条含图像类型、4 个可见性字段及空临床推断字段 |
| 症状字段一致 | 73/108 | 106/108 | 包含来源、原文、状态、程度、频率和时间 |
| 症状原文引用一致 | 18/18 | 18/18 | 原文复制本来就正确，不应归功于训练 |
| 症状来源编号一致 | 15/18 | 18/18 | 原模型有把 I3 写成 I1 的情况 |
| 报告/否定/好转状态一致 | 6/18 | 18/18 | 按本任务明确的状态定义评分 |
| 程度字段一致 | 11/18 | 16/18 | 仍有将“偶尔”当成程度等错误 |
| 频率字段一致 | 12/18 | 18/18 | 小样本中频率对应改善 |
| 时间字段一致 | 11/18 | 18/18 | duration 在本任务也包含“昨日”等原文时间短语，并非完整医学病程解析 |
| 纠正陈述＋证据完整一致 | 2/6 | 5/6 | 陈述内容、引用编号与引用原文一起符合目标 |
| 引用任务编号单独一致 | 5/6 | 5/6 | 单独编号指标没有提高，不能声称所有引用都更准 |

症状完整目标（含格式及所有字段）由 0/6 到 5/6；但原模型六条都输出根数组，而要求是 `{"facts":[...]}` 对象。为避免把格式问题算成全部语义错误，**字段评分兼容读取原模型的数组，也兼容读取视觉输出根层的头盔字段**。原始回答没有修改。最初严格结构评分保存在 `audit_strict_structure.json`；最终 `audit.json` 分开报告格式和内容。

这些字段是工程标签：状态 reported 表示文本明确报告了该状态，睡眠良好也可以是 reported；negative 专指否认/没有等，不是临床上“没有病”的判断。评分包括字段取值约定和原词引用，不能直接解释为医学诊断准确率。

## 改善与仍然失败的例子

- 新眼部局部照片中鼻、嘴未显示。适配器在原提示下正确输出 not_visible；换一种措辞后又输出 unknown。没有补成 visible，但提示稳定性仍不足。
- 示意图判断为 diagram，眼鼻嘴为绘制的可见部位，头盔状态 unknown；不能把图上的脏腑投影当作真人病征。
- 原模型将“我的睡眠质量一般”“近日有时头晕”等标成 negative。适配器对应地提取 reported、一般、有时及原文时间。
- “只有偶尔食欲不佳”被适配器把 severity 也写成“偶尔”，并漏掉另一条“这几天睡眠良好”的程度“良好”。频率和程度仍会混淆。
- 引用测试 `test_c00` 中需要纠正的是“睡眠质量差”，正确来源是“我的睡眠质量一般”。适配器却选择了另一个真实来源“近日有时头晕”。这个编号和引用原文在输入中真实存在，但**纠正的主题错了**。存在的证据不等于相关证据，不能直接用于自动修正患者陈述。

所有未通过的原文保留，没有用规则替换它们以提高成绩。

## 迁移到完整问诊的退化

| 4 条已知问诊提示 | 原模型 | LoRA |
|---|---:|---:|
| 原 7 字段结构仍保留 | 4/4 | 4/4 |
| 有可能解释 | 3/4 | 0/4 |
| 有追问 | 4/4 | 2/4 |
| 出现字面“睡眠质量差”程度改写 | 3/4 | 0/4 |

程度改写消失伴随解释全部消失，不能将 3→0 单独作为完整问诊改善证据。事实训练样本没有覆盖足够的开放问诊行为，适配器倾向少说、不给解释。

具体变化：

- 完整照片的文字描述原来被补成“头发长度及肩”，适配器只保留输入有依据的朝向和微笑；但是解释和追问都为空，还说“无法判断头盔与症状关联性”，产生了不必要的关联问题。
- 原始面图从五官全 unknown 变成眼鼻嘴 visible，保留两条追问，其中“睡眠质量一般”没有被改成“差”；仍需评估追问是否足够开放。
- 已知局部脸图从鼻、嘴 visible 改成五官 not_visible；同时不再解释、不再追问，视觉字段改善没有恢复问诊可用性。
- 偏蓝图的文字描述保留症状原文，给出两条追问，但原来的两条解释消失。

因此目前**不直接给完整问诊挂上这个适配器**。它适合继续测试专门的视觉可见性、症状提取和证据核验任务；自动使用时仍需原文核对和人工复核，尤其防止引用主题错位。

## 后续改进方向

1. 增加独立图片与逐区域标注，覆盖单眼局部、遮挡、侧脸、低分辨率、示意图及非人脸，减少重复图片比例；视觉编码器是否需要训练应在更大样本上判断。
2. 增加程度/频率对照、跨句好转/否定、口语描述及编号乱序，并设置“证据存在但主题不相关”的困难负例。
3. 混入经过审核的开放追问及信息不足回答，让模型学会保留有用追问，而不是全面压缩解释。没有医生审核的病例，不给它编造辨证训练答案。
4. 采用更大、按患者划分的独立集合，同时评估字段正确、完整回答覆盖、误拒、症状改写和诊断依据。测试集不能用于调整训练后再反复宣称独立验证。

本轮已经证明小规模监督训练能够改变这些专门任务的输出；还没有证明完整问诊或诊断能力提高。
