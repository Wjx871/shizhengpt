# 第二轮优化：症状事实、追问前提及视觉输出范围

2026-10-08。针对原面部图像、文字与图文联合流程；不涉及舌诊数据标签。

完成 v3 实现及服务器成对测试，新增 **32 次真实模型推理**。结果显示视觉输出范围约束有效减少了这组已知错误，但没有证明文字问诊质量提高：旧版十个文字/联合条件都保留完整回答，新版只有八个。随后新增 v3.1，对失败分析中的追问单独检查，在原有记录上恢复两组追问，仍不展示失败的解释。

推荐研究入口：[guarded_consultation_v31.py](../scripts/guarded_consultation_v31.py)。[使用说明](consultation_facts_usage.md)。所有模型内容仍需复核。

## 已实现

1. 症状原文、S 编号和有限词表提取的事实槽位并存。槽位保存症状词的原文位置、报告/否定/已缓解状态，以及分句中的程度、频率和时间词；提取未覆盖的内容仍保留在原文中。
2. 按引用的 S 编号检查解释中的症状词，检查部分新增程度、频率和病程；仅有否定/已缓解词的引用来源不能作为当前症状解释依据。
3. 按每个症状前的措辞检查问句前提。允许“是否有胸痛？”，阻止没有胸痛依据时的“胸痛是否持续？”；全句包含“是否”不再能使所有症状免于检查。
4. 视觉描述不再允许服装/头盔内容和部分正常/无异常判断；低分辨率图像限制细节断言，要求看不清的内容写“无法判断”。这是输出范围约束，没有增加独立视觉核验器，也没有改变现有图像质控阈值。
5. v3.1 在完整解释失败时单独检查追问。只有完整 JSON、未截断、非空且通过追问检查的内容才保留；失败解释、模型自写的失败分析限制说明都不被提升为有效内容。额外检查不调用模型。

v2、v3 和 v3.1 均保留，历史输出不被覆盖，没有训练、修改权重或改动 BF16/推理后端。

本次没有发现旧版保留文字回答触发新增规则，因此**不能声称文字幻觉率下降**。新规则在构造负例中能发现否定、引用及错误前提，但实测也带来了误拦截；需要后续独立人工标注来评估收益。

## v3.1 追问单独保留

这是根据本轮发现进行的工程后处理，单独保存于 `consultation_facts_v31_replay_20261008`。它复用已经生成的 v3 候选，新增推理次数为 **0**，不能作为 v3.1 的独立验证。

- 8 个条件保留原来完整分析；没有修改这些模型文本。
- h05、h06 从最后一个候选中分别保留 3 个通过单独检查的追问；解释保持为空。
- h05 可继续询问“食欲下降具体指哪些食物或餐次？”、“是否有伴随恶心、反酸等消化不适？”等。
- h06 可继续询问“睡眠质量具体指什么？”、“是否有夜间易醒或多梦的情况？”和白天疲乏的伴随情况。
- 两个条件的状态为 `questions_only_after_explanation_rejection_requires_review`，明确标记只有追问，不应展示为完整有效分析。

因此回放中 10/10 条件有可用追问，只有 8/10 有完整分析；不能把它简写成“10/10 问诊成功”或“准确率 100%”。模型调用仍是冻结 v3 原有 16 次，没有重生成或覆盖原始记录。

## 局限及下一步

有限词表不能覆盖全部症状、近义词、程度变化、跨句指代和隐含前提。分句内的时间/频率词也不一定已经准确绑定到某一个症状。检查主要覆盖解释和追问，对模型限制说明的事实性检查不完整。

视觉描述变短和减少无异常断言来自约束输出范围，不能证明视觉识别能力提高。颜色、光照、遮挡仍未得到医学校准；没有使用专家确认的疾病/证候真值。

下一步优先处理：跨句状态关联；睡眠“良好→一般”这类程度对照；区分“解释中待核实的条件”和“已存在的患者事实”；追问的表达完整性。随后另建一批冻结的新合成条件和独立患者样本，由人工盲评症状错误、视觉断言错误、误拒及回答覆盖率。已有开发案例继续作为回归检查，不重复包装成新独立测试。
