# 事实与证据核对 v4（实验入口）

这是工程流程优化：保留基础权重，先进行面部图片质控和独立视觉观察，再基于症状原文分析。模型的图片描述不作为辨证证据。没有临床诊断参考答案，不代表诊断能力提高。

相比此前流程，新增对同一症状条目内单一症状的跨句缓解状态关联；对追问中“睡眠良好→一般/差”的检查；每条解释附来源编号与逐字引用，检查引用是否属于对应来源、是否仅以否定或已缓解症状作为正向依据。未知伴随情况放在待补充信息或中性追问中。最多重试一次，失败时尝试单独保留检查通过的追问。

这些检查只覆盖有限词表和明确表达：逐字引用正确，不等于引用足以支持医学解释；图片通过质控，也不等于视觉断言正确。歧义的跨句指代不自动处理。

## 自定义实验

在服务器已有聊天服务运行时执行（不另外加载一份模型）：

```bash
cd /root/private_data/shizhengpt-evaluation
.venv/bin/python scripts/run_alignment_v4.py \
  --symptoms-json /path/to/symptoms.json \
  --image /path/to/face.jpg \
  --output evaluation/outputs/alignment_v4_custom.json
```

纯文字可省略 `--image`，纯图片可省略 `--symptoms-json`。症状文件示例：

```json
["三天来轻微疲劳，休息后减轻", "睡眠良好", "没有发热"]
```

输出同时保存模型原始候选、有限检查拒绝原因、最终保留内容、追问降级状态和耗时。`questions_only_requires_review` 只表示保留追问，不能当作完整分析通过。`qc_abstention` 表示图片质控弃答，不是视觉判断正确。

实验入口现在默认使用 v4.1：完整候选被拒绝后，对解释和追问逐项检查，保留同一候选中通过检查的项目，避免一项失败拖累整段回答。此时状态为 `partial_checked_content_requires_review`，不能算完整回答通过。可传 `--version v4` 复现上一版处理。

固定 v4 对照的输出保持不变；v4.1 在其上的回放属于事后分析，新增推理为零。另有 4 个运行前冻结的后续合成条件，保存于 `alignment_engineering_v41_forward_20261009`。后续条件是在看到 v4 早期问题后设计的，仍不是独立临床评测。

## 固定回归评测

`evaluation/alignment_engineering_v4_20261009/manifest.json` 保存 12 条固定输入：6 个合成文字条件、4 个已知公开图片回归条件、2 个图文组合。图片人物与合成症状没有病例关联。这些是开发回归集，不能作为独立泛化测试集。

运行前冻结输入哈希、提示/规则代码哈希和对照协议。两组都使用基础模型、相同 JSON 格式及分开的视觉/文字阶段，每次调用为新会话、768 token 上限。增强组增加事实槽位、质控、检查及一次重试。对照属于组合干预，不能单独归因某条提示或某个规则。

```bash
.venv/bin/python scripts/evaluate_alignment_v4.py
.venv/bin/python scripts/audit_alignment_v4.py
```

评测可按已保存条件续跑，历史输出不会覆盖。程序同时记录原始首次候选、最终保留内容、明确视觉错判、unknown/弃答、引用结构错误、完整回答/追问覆盖率及调用成本。预先列出的错误措辞只是筛查，需要逐条复核；自有规则的通过率不能当作幻觉率。

聊天网页仍使用原始模型直接回答；v4 在独立实验入口验证。
